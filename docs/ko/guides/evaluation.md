# 분석 품질 평가

공개 샘플 질문은 회귀 검증용이며 비공개 정답으로 평가하는 벤치마크가 아닙니다. Complete Journey는 관측 데이터이며 인과 효과의 정답을 제공하지 않습니다. 알려진 기준값을 맞혔다는 사실만으로 AI 정확도가 향상됐다고 주장할 수 없습니다.

## 실제 AI 클라이언트로 확인

[샘플](https://github.com/haechangcho/decision-layer/blob/main/examples/complete-journey/README.ko.md)을 실행하고 MCP 어댑터를 설치한 뒤 Claude Code에 로그인하세요. 저장소 루트에서 실행합니다.

```bash
DL_API_URL=http://127.0.0.1:8000 .venv/bin/python evals/run_eval.py \
  examples/complete-journey/evals/scenarios.json --repeats 3
```

실제 API 포트를 사용하세요. 이 명령은 실제 AI 클라이언트를 호출해 사용량을 소비하며 CI에 포함되지 않습니다. 도구 호출, 답변, 휴리스틱 검사 결과는 Git에서 제외된 예제의 `evals/results/`에 저장됩니다. 모집단·분모가 맞는지, 근거 없는 해석이 없는지는 사람이 검토해야 합니다. 공개 질문의 통과율은 일반적인 분석 정확도의 증거가 아닙니다.

## 비교 실험

독립 검토한 같은 질문을 동일 모델·버전·언어·도구 및 시간 예산·읽기 전용 권한으로 실행합니다. 조건의 실행 순서를 무작위로 배치하고 질문을 반복하세요.

| 조건 | 제공할 정보와 도구 |
| --- | --- |
| 직접 분석 | 읽기 전용 원본 DB, 스키마, 데이터 제공처 문서 |
| Semantic layer + Method | Semantic catalog와 등록된 Decision Layer Method |
| Semantic layer + Method + Recipe | 같은 catalog와 Method, 검토한 Recipe |

현재 평가 실행기는 Decision Layer 경로를 검증하며 직접 SQL 분석의 전체 비교군을 제공하지는 않습니다. 첫 번째와 두 번째 조건의 비교는 의미 정보와 실행 계약을 모두 바꾸므로 Recipe의 효과만 분리할 수 없습니다. 재사용 절차의 효과는 두 번째와 세 번째 조건을 비교하세요.

검토자만 아는 평가 질문은 공개 개발 질문과 분리합니다. 독립 SQL 기준값, semantic 참조, 기간, grain, 분모, 경고, 타당한 실행 거절, 근거 없는 인과 주장 여부를 평가하세요. 캠페인 선택, 결측 인구통계, 상대 일자, 모집단 규모 차이, 수취액과 이익의 차이도 포함합니다. 확신에 찬 오답은 중대한 실패입니다.

수치로 된 성능 주장을 공개하려면 충분히 다양한 검토 질문을 사용하고 대화 전문과 Run ID를 남기세요. 클라이언트·모델 버전, 조건, 반복 횟수, 채점 방식, 불확실성, 시간·비용, 실패와 한계를 함께 보고합니다. 평가 중인 에이전트에게 기준 정답을 제공하지 마세요. 하나의 소매점 데이터셋 결과를 모든 도메인의 인과 정확도로 일반화하면 안 됩니다.
