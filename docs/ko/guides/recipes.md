# Recipe 만들기

**Method**는 추이나 드릴다운처럼 하나의 분석을 실행하는 기능입니다. **Recipe**는 조직이 반복해서 묻는 질문에 대해 어떤 지표로 어떤 순서의 분석을 할지 기록한 절차입니다.

## 지표에서 시작하기

1. [Metrics](http://localhost:3000/catalog)에서 지표를 선택하고 **Recipe 만들기**를 누르세요.
2. 그래프에 분석 단계를 추가하세요. 차원을 고르면 드릴다운, 다른 지표를 고르면 추이를 제안합니다.
3. 각 단계의 필수 입력을 선택하고 **결과 확인**을 누르세요. 기간과 실행 입력은 필요한 경우에만 받습니다.
4. 초안으로 저장해 검토한 뒤 게시하세요.

그래프의 선은 실행 순서와 지표 연결을 보여줍니다. 일반적인 워크플로 엔진이나 인과 관계를 뜻하지 않습니다. 정렬·범위 연결과 전체 파라미터는 **코드 보기**에서 확인·수정합니다. 일반 설정을 바꿔도 기존 세부 설정은 유지됩니다.

## Run에서 가져오기

완료된 [실행 기록](./runs.md)에서 **Recipe로 등록**을 누르면 팝업 없이 바로 저장합니다. 기본은 이번 결과값을 고정하는 대신 실행할 때 분석 대상을 다시 선택하는 절차입니다. 기록된 규칙은 보존하고, semantic 차원의 경로가 맞으면 앞 단계의 선택 결과에 연결합니다. 앞 단계에서 가져올 수 없는 대상은 고정된 기본값 없이 필수 runtime 입력으로 만듭니다. MCP는 Recipe 실행을 시작할 때 이 입력을 전달하고, Web도 같은 입력 계약을 사용합니다.

Recipe에서 명시적으로 고정한 Method 설정과 나머지 분석 설정은 유지합니다. 실행 당시의 기간과 공통 필터는 자동 고정하지 않습니다. 이미 등록한 Recipe는 덮어쓰지 않고 반환합니다. 고정 대상이나 세부 설정을 바꾸려면 **편집해서 저장**을 선택하세요.

## 이전 값 대신 선택 규칙 저장하기

“최고 부문을 찾고, 그 안의 최고 매장을 비교”하는 절차는 데이터가 바뀌면 대상을 다시 찾아야 합니다. 다음 단계의 분석 범위를 이전 결과에서 가져오도록 설정할 수 있습니다.

```yaml
params:
  drill_path:
    source: step
    step_id: by_group
    output: ranked_groups
    select: first
    project: path
```

`path`는 선택한 전체 경로, `condition`은 선택한 그룹만, `parents`는 상위 조건만 가져옵니다. 동료 비교에서는 대상에 `condition`, 동료 집단 조건에 `parents`를 지정하세요. 전체 집단 비교 범위가 좁아지지 않도록 탐색 중 선택한 조건은 Run의 공통 필터로 옮기지 않습니다.

일반 드릴다운은 표시할 행 수와 관계없이 적격 그룹의 순위 결과를 제공합니다. 결과가 없거나 실패했거나 일부만 조회됐다면 다음 대상을 자동 선택하지 않습니다. 1위가 동률이면 입력을 요청합니다. 기간별 기여도 드릴다운의 순위 참조는 아직 지원하지 않습니다. 기존 `$steps` 표현식은 유지하지만 완전한 후보 집합을 보장하지는 않습니다.

고급 설정의 **실행할 때 받을 입력**에서 입력을 선언하면 단계 설정에서 **실행 시 입력**으로 선택할 수 있습니다. Web이나 MCP의 `start_run(inputs=...)`에서 실제 값을 받습니다. Run에는 원래 규칙과 적용값이 모두 남으며, 다시 Recipe로 등록해도 규칙이 유지됩니다.

Recipe는 버전이 있는 YAML 파일입니다. 실행 결과는 별도의 Run 저장소에 남습니다. 웹에서 저장한 Recipe 파일은 자동으로 Git 커밋이나 PR을 만들지 않습니다. 팀 검토가 필요하면 Recipe 폴더를 Git으로 관리하세요.
