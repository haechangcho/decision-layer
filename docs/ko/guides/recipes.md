# Recipe 만들기

Recipe는 반복하는 분석을 순서로 정리한 절차입니다. 예를 들어 “매출이 가장 큰 상품을 찾고, 그 상품의 지역별 매출을 비교한다”는 분석을 저장해 재사용할 수 있습니다.

## 지표에서 시작하기

관리자 화면에서 다음 순서로 만듭니다.

1. **지표**에서 분석할 지표를 선택하고 **Recipe 만들기**를 누릅니다.
2. 분석 단계를 추가하고 각 단계의 Method와 입력을 선택합니다.
3. **결과 확인**으로 실행하고, 결과와 검증 내역을 검토합니다.
4. 초안으로 저장한 뒤 게시합니다.

그래프는 분석 순서와 입력 연결을 보여줍니다. 단계의 세부 설정은 **코드 보기**에서 확인할 수 있습니다.

## 실행한 분석을 저장하기

완료된 [Run](runs.md)에서 **Recipe로 등록**을 선택하면 같은 분석 절차를 저장합니다. 저장 전에 구성을 바꾸려면 **편집해서 저장**을 선택합니다.

실행한 날짜와 그때 선택한 상품을 다음 분석에도 고정할 필요는 없습니다. 실행할 때 새 기간이나 대상을 받도록 할 수 있습니다.

## 결과값보다 선택 방법을 남깁니다

1월에는 A 상품이 매출 1위이고, 2월에는 B 상품이 1위일 수 있습니다.

“A 상품을 분석한다”를 저장하면 다음에도 A를 분석합니다. **“매출 1위 상품을 찾아 분석한다”**를 저장하면 매번 순위를 확인해 대상을 선택합니다.

1위가 동률이거나 결과가 충분하지 않으면 자동으로 대상을 정하지 않고 입력을 요청합니다.

<details>
<summary>앞 단계의 선택 결과를 연결하는 YAML</summary>

```yaml
params:
  drill_path:
    source: step
    step_id: by_group
    output: ranked_groups
    select: first
    project: path
```

`path`는 선택한 전체 경로, `condition`은 해당 그룹, `parents`는 상위 조건을 가져옵니다. 동료 비교에서는 대상에 `condition`, 동료 집단에 `parents`를 사용합니다.

이 연결은 Method가 선언한 선택 결과를 사용합니다. 실패했거나 일부만 조회된 결과에서 다음 대상을 고르지 않습니다.

</details>

## 팀에서 재사용하기

Recipe는 버전이 있는 YAML 파일로 저장됩니다. 실행 결과는 별도의 Run에 남으므로, 같은 절차를 다른 기간과 입력으로 실행해 비교할 수 있습니다.

프로젝트 파일을 Git으로 관리하면 팀의 검토 절차를 적용할 수 있습니다. 관리자 화면에서 저장한 파일이 자동으로 Git에 커밋되지는 않습니다.

[실행 기록과 근거](runs.md)에서 각 분석에 어떤 입력과 쿼리가 사용됐는지 확인하세요.
