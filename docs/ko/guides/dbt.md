# dbt Semantic Layer 연결

회사에서 운영하는 dbt Semantic Layer의 공식 GraphQL API에 연결합니다. Decision Layer가 지표와 차원을 조회하고 분석 요청을 보내면, dbt가 SQL 생성과 데이터 조회를 처리합니다. 결과와 실행 근거는 Run에 남습니다.

별도 게이트웨이 설치, dbt 프로젝트 업로드, 데이터베이스 계정 제공, Decision Layer 전용 메타데이터 추가는 필요하지 않습니다.

## 연결하기

기존 소스에 연결할 때는 저장소 루트에서 앱을 실행합니다.

```bash
docker compose up -d --build --wait
```

저장소 루트의 명령은 웹과 API만 실행합니다. 샘플 데이터가 필요하면 `examples/complete-journey`의 [로컬 예제](../index.md)를 사용하세요.

[연결 설정](http://localhost:3000/sources)에서 **dbt Semantic Layer**를 선택하고 다음 정보를 입력합니다.

| 항목 | 입력할 값 |
| --- | --- |
| API 주소 | 사용 중인 dbt 배포 환경의 Semantic Layer GraphQL 주소 |
| 환경 ID | 시맨틱 모델을 배포하고 Semantic Layer를 설정한 환경의 ID |
| 연결 이름 | 저장한 지표 참조에 사용할 고정 이름. 예: `analytics-production` |
| 접근 토큰 | 해당 환경에 접근할 수 있는 dbt 서비스 토큰 또는 개인 토큰 |

북미 멀티테넌트 환경의 주소는 `https://semantic-layer.cloud.getdbt.com/api/graphql`입니다. 다른 리전이나 전용 배포는 주소가 다릅니다. dbt 연결 설정에 표시된 주소를 사용하세요. Administrative API 주소와는 다릅니다.

**연결 테스트 → 설정 저장 → 지표 탐색** 순서로 진행합니다. 토큰에는 해당 환경의 Semantic Layer와 메타데이터 접근 권한이 필요합니다. 정확한 주소와 토큰 권한은 [dbt 공식 안내](https://docs.getdbt.com/docs/dbt-apis/sl-graphql)를 참고하세요.

토큰은 요청마다 dbt로 전달하며 현재 브라우저 탭에만 보관합니다. Decision Layer의 DB에는 저장하지 않습니다. 공용 서비스 토큰을 쓰면 같은 접근 권한과 실행 기록 소유자를 공유합니다. 사내 사용자별 로그인이나 권한 분리 기능을 대신하지 않습니다.

## MCP로 분석하기

[MCP 설정](mcp.md)에 따라 연결하고, 클라이언트의 비공개 환경 설정에 같은 토큰을 `DL_TOKEN`으로 지정하세요. `DL_API_URL`은 dbt 주소가 아니라 Decision Layer API 주소입니다. 로컬 앱은 `http://localhost:8000`을 사용합니다.

AI 도구에 사용 가능한 지표를 확인하고 등록된 Method로 분석하도록 요청하세요. Run에는 질문·설정·지표 참조·dbt 쿼리 ID와, 요청 시 dbt가 반환하는 SQL이 기록됩니다. 웹과 MCP는 같은 실행 엔진을 사용합니다. 같은 기록을 보려면 같은 연결과 토큰을 사용하세요.

## 지원 범위

- 페이지가 여러 개인 지표·차원 카탈로그 조회
- 범주별 집계, 지원되는 시간 단위, 기간, 정렬과 결과 페이지 조회
- 범주형 차원의 값 일치·불일치·크기 비교·빈 값 필터
- 쿼리 제출, 완료 상태 조회, 쿼리 ID를 포함한 실행 근거
- 공통 Method를 통한 드릴다운·추이·기술적 집단 비교

자유 형식 SQL·Jinja 입력과 개체 단위 데이터 추출은 지원하지 않습니다. 통계 분석에는 표본과 분석 단위를 확인할 수 있어야 합니다. `SIMPLE`이라는 타입만으로 합계나 건수를 추정하지 않으며, 확인되지 않은 정보는 미확인 상태로 둡니다. 접근 가능한 기본 비율 정의의 분자·분모는 보존합니다. 연결을 위해 커스텀 `meta`를 추가할 필요는 없습니다.

공식 GraphQL 계약을 기준으로 오류·페이지 조회·시간 초과 등을 자동 테스트합니다. 실제 운영 연동 검증에는 접근 가능한 dbt 환경이 필요합니다. 로컬 예제가 성공했다고 공식 API 연동까지 검증된 것으로 표시하지 않습니다.

## 환경변수로 설정하기

API 프로세스에서 `DL_SOURCE_PROVIDER=dbt`, `DBT_API_URL`, `DBT_ENVIRONMENT_ID`, `DBT_INSTANCE`를 설정할 수 있습니다. 해당 값은 웹에서 저장한 설정보다 우선합니다. 컨테이너를 사용하면 배포 설정에서 API 컨테이너로 전달하세요. 토큰은 요청 단위로 전달합니다. MCP에서는 `DL_TOKEN`, 웹에서는 접근 토큰 입력칸을 사용합니다.

## 문제 해결

| 상황 | 확인할 내용 |
| --- | --- |
| 인증·권한 오류 | 토큰의 환경 접근 권한과 Semantic Layer·메타데이터 권한 |
| 지표가 없음 | 선택한 환경에 지표가 정의·배포되어 있는지 |
| 주소가 응답하지 않음 | 리전에 맞는 Semantic Layer GraphQL 주소인지 |
| 쿼리 실패 | dbt에서 쿼리 ID로 확인하고 지표·차원·필터 조합 점검 |
| 대기 시간 초과 | 재시도 전에 dbt의 쿼리 상태 확인. 클라이언트 대기가 끝나도 원격 쿼리는 계속 실행될 수 있음 |
| dbt Core 프로젝트만 있음 | 공식 API를 제공하는 dbt 플랫폼 환경이 필요합니다. dbt Core만으로는 이 API를 사용할 수 없습니다. |
