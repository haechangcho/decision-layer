# 제품 UX·시스템 마일스톤 체크리스트

계획: [`PRODUCT_UX_IMPLEMENTATION_PLAN.ko.md`](PRODUCT_UX_IMPLEMENTATION_PLAN.ko.md)  
원칙: 사용자 시나리오가 끝까지 통과하기 전에는 마일스톤을 완료로 표시하지 않는다. 코드 검토만 한 항목은 완료 처리하지 않는다.

## 다음 작업 순서 · 2026-10-01 갱신

1. U2/U3: Recipe 기본 작성 흐름 단순화와 혼란스러운 용어 개선
2. U1/U3: 기본값·고정값·AI 선택 범위 및 실제 적용값 기록
3. U3: 미리보기·검증·diff·YAML·발행 완성
4. U4: MCP 실행 기록 그래프 → Recipe 그래프 초안 → 사용자 검토·승인 → 등록
5. U5: Method 기여 경험과 Docker 운영

사용자 요청으로 Sources S2/S3(기업 OIDC·토큰 자동 갱신·공용 서비스 계정)를 개발 범위에서 제외했다. 기존 인증·권한 검사를 제거하는 변경은 아니다.

이 순서 변경은 아래 기존 완료 항목을 취소하거나 신규 항목을 완료로 표시하지 않는다.

## U0 · 계획과 제품 경계

- [x] 현재 구현과 ADR·제품 문서 차이 기록
- [x] 사용자 유형별 여정과 화면 책임 정의
- [x] Recipe·Method·Run·semantic layer·Git·DB 책임 경계 정의
- [x] MVP와 후속 범위, 사용자 기준 완료 시나리오 정의
- [x] 검토를 막는 정책 결정 식별
- [x] 구현 계획과 이 체크리스트 저장

## U1 · 공통 Recipe 계약

- [x] Sources S1: 명시적 API URL·인증 선택, 자동 주소 탐색 제거, 검사와 실행의 인증 일치 ([검토 문서](SOURCE_CONNECTION_DESIGN.ko.md))
- S1 검증 완료 (2026-10-01): 연결 화면을 배포 형태별로 구분(환경변수 고정=상태만 / 로컬=키 없이 편집 / 공유 서버=관리자 키). 실제 hc-cube로 토큰 인증 전체 흐름 확인: 사용자 토큰 → 연결 테스트 → 카탈로그 51개 → 지표 미리보기(반품률 9.06) → 준비 상태 17개, 잘못된 토큰은 연결 테스트·카탈로그 모두 거부(검사/실행 인증 일치). source-connection Playwright 3상태 + live 테스트, 서버 테스트 14개 통과.
- [x] 파일 로딩·API 검증·저장이 공통 정적 검증 서비스 사용
- [x] 도메인 검증 오류에 단계/필드 경로와 해결 가능한 메시지 포함
- [x] `POST /recipes:validate`로 저장 전 정적 검증 제공
- [x] 선택적 semantic live preflight와 정적 검증을 구분
- [x] 최신 파일을 잠금 아래 다시 읽고 base version으로 오래된 저장 거부
- [x] 애플리케이션 저장은 기존 버전을 덮지 않고, 외부 YAML 변경은 다음 조회부터 반영
- [ ] API 시나리오: 파일에서 유효 Recipe 로드 → Web 저장 검증 → 오래된 버전 저장 거부

## U2 · Recipe 찾기와 사용

- [x] 루트 화면을 Recipe 실행 라이브러리로 연결
- [x] 일반 사용자 실행 화면과 전문가 편집 화면 분리
- [x] 저장 Recipe 상세를 실행 화면으로 변경하고 편집 경로 분리
- [x] 기간 입력·프리셋·날짜 기준 선택과 202/완료 Run 상세 연결
- [x] Method manifest role/기본 파라미터를 기반으로 편집 폼 생성
- [ ] 기본 작성 흐름을 사용 목적 → 분석 대상 → 분석 절차로 변경
- [ ] 초기 화면에서 '순서대로 실행 / 단계별 조사' 선택 제거. 기존 investigation 정의와 MCP 진입 경로 유지
- [ ] 표시할 그룹 수·최소 그룹 건수·정렬 기준을 고급 설정으로 이동하고 기본값 복원 제공
- [ ] '기본 분류 순서'를 '먼저 살펴볼 항목 (선택)'으로 개선하고 고정 드릴다운 경로와 구분
- [ ] E2E: 모드 용어와 숫자 파라미터를 모르는 전문가가 지표 비교·항목별 분석 두 단계를 작성
- [ ] 실행 완료·202 진행·실패·권한 부족 상태에서 다음 행동 제공
- [ ] E2E 시나리오: Recipe 검색 → 최소 입력 → 실행 → 결과·근거 확인
- [ ] E2E 시나리오: 작성 권한 사용자는 같은 Recipe의 편집 화면 진입

## U3 · Recipe 작성·검증·발행

- [ ] 생략값은 Method 버전별 기본값으로 해석하며 Web·REST·MCP에서 같은 결과 적용
- [ ] Recipe 고정값·실행 시 선택값의 최소 계약과 override 충돌 검증 (스키마 변경 시 ADR 추가)
- [ ] AI가 변경 가능한 옵션 범위와 최소 표본·실행 한도 정책을 서버가 검증
- [ ] Run에 적용값·값의 출처·절단/제외 여부·경고 기록
- [ ] 기존 Recipe를 열고 저장해도 숨겨진 파라미터와 단계 설정 보존
- [ ] 지표를 실행 시 선택할 때 필수 role과 허용 semantic 범위를 검증
- [ ] pipeline/investigation 전환에서 기존 정의 보존 또는 명시적 복제
- [ ] 단계별 검증 오류와 실행 미리보기
- [ ] JSON 고급 편집을 canonical YAML 편집과 양방향 동기화
- [ ] 의미 있는 Recipe diff, 초안/발행 상태, 발행 이력
- [ ] E2E 시나리오: 두 단계 Recipe 작성 → 미리보기 → 오류 수정 → diff 확인 → 발행 → 새 버전 실행

## U4 · MCP Run 검토와 Recipe 전환

- [ ] Recipe 우선 사용, Recipe가 없으면 허용된 Method·semantic 객체로 탐색
- [ ] 세부 옵션은 기본값으로 진행하고 분석 의미가 모호할 때만 사용자에게 질문하도록 도구 설명·예제 보완
- [ ] 계약 테스트: AI의 잘못된 옵션·고정값 override·정책 미달 요청이 Web/API와 동일하게 거부됨
- [ ] MCP 실행 출처·탐색 세션 식별
- [ ] Run 상세에 읽기 전용 실행 그래프, 노드별 입력·결과·경고·근거 표시
- [ ] 별도 adhoc Run을 사용자 선택으로 묶고, 실행 순서와 실제 참조 간선 구분
- [ ] 명시적으로 제출/공유된 Run 검토 목록
- [ ] 선택 단계로 Recipe 초안 생성, 원본 Run 연결
- [ ] 기존 Recipe 그래프 편집기에서 새 Recipe/기존 Recipe 추가 제안 검토
- [ ] 미발행 제안 DB 저장 계약과 ADR: 후보 spec·revision·base version·원본 단계·검토 상태
- [ ] 민감 scope·기간 값을 재사용 입력으로 바꾸는 검토
- [ ] 권한·semantic 참조 재검증과 초안 테스트
- [ ] '승인하고 Recipe 등록'에서 검토한 revision만 YAML 새 버전으로 발행, 승인자·시각·발행 버전 기록
- [ ] 보류·반려·수정 후 재검증, 원본 Run 보존
- [ ] 중복 승인·동시 편집 충돌·파일 저장 실패·무권한 요청의 멱등성 및 복구 검증
- [ ] E2E: MCP 탐색 → 기록 그래프 → 두 단계 선택 → 초안 수정 → 승인 → 새 Recipe 실행
- [ ] E2E: 승인 전에는 Recipe 목록/실행에 미노출, 반려 시 원본 Run 보존, 기존 Recipe 추가는 새 버전만 생성

- [ ] 관리 설치 및 버전 고정 문서
